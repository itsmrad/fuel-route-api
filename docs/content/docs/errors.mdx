---
title: Errors
description: Every error is JSON with a machine-readable code and a human-readable detail.
icon: TriangleAlert
---

```json
{ "error": "unknown_location", "detail": "Could not resolve \"Springfeld, ZZ\" to a US location." }
```

`error` is stable and safe to branch on. `detail` is for people and may change.

| Status | `error` | When | What to do |
| --- | --- | --- | --- |
| `400` | `missing_parameter` | `start` or `finish` is missing or empty. | Send both query parameters. |
| `400` | `invalid_parameter` | `stop_penalty` is not a number, or is negative, `nan` or `inf`. | Send a number `>= 0`, or leave it out for the default `15`. |
| `400` | `unknown_location` | The input is not a known `City, ST`, not `lat,lon`, and Nominatim found nothing in the USA. | Use `City, ST` with a two-letter state, or coordinates. |
| `422` | `unreachable` | Some stretch of the route has no station within the 500-mile range. | Nothing to retry. `detail` names the gap's mile markers. |
| `422` | `no_route` | No road connects start and finish (Hawaii to the mainland). | Nothing to retry. |
| `502` | `routing_provider_error` | Both OSRM servers (and Valhalla for trucks), or Nominatim, failed or timed out. | Retry after a second; the public OSRM server allows 1 request/s. |

## From the docs site

When the route planner or the API playground gets no JSON back at all (Django not running, wrong `API_ORIGIN`), the Next.js proxy answers with a `500` HTML page. The planner reports that as "The API isn't running" with the command to start it.
