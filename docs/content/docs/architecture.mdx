## The request path

1. **Resolve** `start` and `finish`. `City, ST` matches the Census table built by `load_stations`; `lat,lon` is parsed directly. Only other inputs fall back to Nominatim, one call each.
2. **Route** with OSRM `/route/v1/driving` (default, `vehicle=car`), or Valhalla `costing=truck` (`vehicle=truck`): one call, full geometry, distance and duration. If Valhalla fails, or the trip is over its 1,500 km public-server cap, the route comes from OSRM car and `routing.fallback` is `true`.
3. **Find stations along the route.** An in-memory grid index (0.5° cells) narrows the 6,443 stations to the cells the route crosses; a station is kept when it lies within 10 miles of the polyline, and its mile marker is the cumulative distance of the nearest route point.
4. **Optimize** the stops with the dynamic program described in [How the optimizer works](/docs/optimizer).
5. **Respond** with JSON. The route (distance, line, corridor stations) is cached on the vehicle and resolved coordinates, so another spelling or `stop_penalty` re-runs only the optimizer. `/api/route/map/` reads the same entry.

Internally the steps are three plain functions: `resolve(query) → {lat, lon, external}`, `get_route(a, b, vehicle) → {coords, distance_miles, duration_hours, routing, calls}`, and `plan_fuel_stops(...)`. `external_api_calls` is `1` for the route (`2` when a truck route fell back to OSRM) plus `1` for each location that needed Nominatim.

## Where the time goes

| Stage | Cost | Notes |
| --- | --- | --- |
| OSRM route | ~0.6–1.7 s | Public demo server. Dominates every cold request. |
| Valhalla truck route | ~0.8–2.3 s | Dallas → Chicago, p50 1.1 s vs 0.6 s for OSRM. Over 1,500 km it is skipped. |
| `stations_along` | 18–30 ms | Dallas → Chicago keeps 189 corridor stations, NYC → LA 447. |
| Optimizer | 10–25 ms | O(n·F) DP: n corridor stations × 501 fuel levels. |
| Cache hit | 15–40 ms | No external calls; the optimizer re-runs. |

## Decisions

| Topic | Decision | Why |
| --- | --- | --- |
| Starting fuel | Full tank (500 mi) | "Total cost" is fuel bought on the way. `cost_of_fuel_consumed` covers short trips. |
| Input | `City, ST` or `lat,lon` resolved locally | Zero calls for the common case. Nominatim only as a fallback. |
| Routing | OSRM public server; Valhalla truck opt-in | No key, full geometry in one call. Truck is opt-in because the public Valhalla server rejects trips over 1,500 km (every coast-to-coast trip). |
| Framework | Plain Django + `JsonResponse` | One endpoint. DRF would add more than it gives. |
| Storage | SQLite `Station` table, loaded into memory on first request | 6.4k rows. Idiomatic, no extra service. |
| Spatial search | Stdlib grid index | PostGIS, scipy or numpy are not needed for 6.4k points. |
| Cache | Django file cache | Shared by gunicorn workers on one server. Redis when there are two. |
| Money | `Decimal` end to end | Prices have 8 decimal places; never mix `Decimal` and `float`. |
| CORS | None | The browser only talks to its own origin; `/api/*` is proxied. |
| Dependencies | `django`, `requests`, `gunicorn` | Nothing else. |
