Measured 2026-10-21 from a dev laptop (Darwin arm64, Python 3.14.7) against the public OSRM demo server; network-dominated. gunicorn `-w 2 --threads 4 -k gthread` (the Docker image's config), `DEBUG=0`, a fresh file cache, one client, sequential requests.

Method: each route is requested once cold (1.5 s apart; 12 external calls in the whole run), then 20 times cached, then once per `stop_penalty` in [0, 15, 40]. Compute stages are timed in-process on the cached routes. Percentiles are nearest-rank. Reproduce with `CACHE_DIR=<server cache> uv run python manage.py benchmark --url <server> --clear --write`.

## Server-side compute

p50 over all cached requests, in-process (no HTTP). `stations_along` runs only on a cache miss; here it is timed on the cached response line (at most 5,000 points), a slight underestimate on long routes.

| Stage | p50 ms | p95 ms |
| --- | ---: | ---: |
| Resolve start + finish (Census table) | 0.01 | 0.02 |
| Route cache read | 0.8 | 1.3 |
| Corridor match (`stations_along`, cold path only) | 5.4 | 11 |
| Optimizer (DP, $15 penalty) | 6.6 | 19 |
| JSON encode (`JsonResponse`) | 1.6 | 2.1 |
| Cached request total (resolve to JSON) | 9.1 | 24 |

## Fuel cost against a naive driver

Same corridor stations, same full tank at the start, 500-mile range, 10 MPG. **Naive rule**: at each corridor station in mile order, fill the tank to full if the finish is out of reach and the next station (or the finish) would be reached with under 100 miles of fuel left; otherwise drive on. Fuel left in the tank at the finish is credited back at the last fill price. The optimizer is the service's DP at the default $15 stop penalty and at $0 (pure cheapest); the penalty is never counted as spend.
